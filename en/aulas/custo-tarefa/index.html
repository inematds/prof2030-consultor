Lesson 4 · 20 min

Model and vendor by cost per task

The owner asks: "which AI should I use?" The answer is not the trendy model or the cheapest per token. It is the one that delivers the task at the lowest total cost, counting the retries and the time of whoever reviews. And the vendor weighs in too: tools get discontinued, data crosses borders, licenses change.

Start the lesson

In this lesson you will

  1. 1The four tiers: frontier, mid-range, cheap, and open local
  2. 2The cost-per-task formula, with human review
  3. 3Why the cheapest token is not always the cheapest task
  4. 4Five vendor risk questions

Goal: calculate the cost per task of 2 processes across 4 model tiers, with human review in the math, and assess the vendor risk.

01 · What goes into the cost of a task

Four parts. Click each one.

1/5

Tokens

A token is the piece of text the model charges for (usually a piece of a word). The input (instruction + document) and the output (response) have different prices, quoted in dollars per million tokens.

Scroll the page: each step below lights up its part of the diagram.

  1. 1/5

    Tokens

    A token is the piece of text the model charges for (usually a piece of a word). The input (instruction + document) and the output (response) have different prices, quoted in dollars per million tokens.

  2. 2/5

    Tier price

    Each model has one price per million input tokens and another for output. The price changes with every release: check the vendor's website on the day you do the calculation, never from memory.

  3. 3/5

    Repetitions

    How many times, on average, the task runs until the output is usable: a new attempt, a request for a fix, chained steps. An agent that makes 6 calls for one task multiplies the cost by 6.

  4. 4/5

    Human review

    Minutes a person spends checking and fixing × their hourly cost. In an SMB, this share is usually bigger than the tokens. A worse model can end up costing more because it takes more work to review.

  5. 5/5

    The whole calculation

    Tokens times price, times repetitions, plus the minutes of whoever reviews. Compare the tiers by the total, not by the token price.

Cost per task = (tokens × price) × repetitions + human review. Fixed cost (local machine, subscription) goes in divided by the month's volume.

02 · The method in four steps

Memorize the method, not the prices: they change every month.

1. Measure the task

Take 20 real examples of the task (no personal data). Count the average size of the input and the output. Most tools show the tokens used in each call.

Also note the volume: how many times a month the task happens.

Horizonte, simulationCustomer support summary: 3,000 input tokens, 500 output tokens, 1,200 tickets per month.

2. Choose the tiers

Top tier (e.g., Claude Opus 5.5, US$ 4 input and US$ 20 output per million). Mid-range (e.g., Claude Sonnet 5.5, US$ 2/10; Grok 4.7, US$ 2/6). Cheap (the small versions from each vendor). Open local (e.g., Qwen3.8-27B, runs on a powerful computer, Apache 2.0 license).

Prices as of Oct/2026, with the source at the end of the lesson.

RuleWrite the date and the price link next to each number.

3. Test the review

Run the same 20 tasks on each tier and time how long a person takes to make the output usable. That time is the part of the cost that the token price doesn't show.

Along the way, note the serious errors: a model that gets a price or a customer name wrong may be out, whatever the cost.

Who reviewsThe same person who will do the work later (at Horizonte, Juliana).

4. Add up and decide

Add tokens, repetitions, and review; multiply by the month's volume. For the local model, add the fixed cost (amortized machine, power, maintenance hours) and divide by the volume.

Then run the winner through the vendor's five risk questions. A low cost doesn't make up for data leaving without a contract.

When local winsData that can't leave the company, very high volume, or a cost that has to be fixed.

03 · Cost-per-task calculator

Paste it into a spreadsheet. The numbers in the simulation next to it are an example: swap in your own.

Formula (spreadsheet)
INPUTS (one row per model tier)
A  input tokens per task
B  output tokens per task
C  input price (US$ per million)   <- check on the website, with date
D  output price  (US$ per million)
E  average repetitions per task (1 = right on the first try)
F  exchange rate (R$ per US$)                 <- today's
G  minutes of human review per task <- measured on 20 tasks
H  hourly cost of whoever reviews (R$)
I  volume per month
J  fixed cost per month (R$)             <- local: machine/36 + power + maintenance

CALCULATION
Tokens (R$)      = (A*C + B*D) / 1000000 * E * F
Revisão (R$)     = G / 60 * H
Fixo por tarefa  = J / I
CUSTO POR TAREFA = Tokens + Revisão + Fixo por tarefa
CUSTO NO MÊS     = CUSTO POR TAREFA * I
Vendor risk questions
1. WHERE DOES THE DATA GO? Server country, contract, legal basis (LGPD (Brazil's data protection law)). Personal data leaving without a contract = stop.
2. CAN THE TOOL BE DISCONTINUED? Is there an announced shutdown date? How do I export instructions and data?
3. IS THE VENDOR STABLE? Dispute with a government, change of owner, IPO, sudden price change.
4. DOES THE LICENSE ALLOW IT? (open model) Commercial use, revenue cap, research only.
5. CAN YOU SWITCH? Instructions in your own file, no exclusive feature -> switch in days, not months.
Simulation: illustrative example

3,000 input tokens, 500 output tokens, 1.2 repetitions, sample exchange rate R$ 5.50, review at R$ 30/h, 1,200 per month. Review minutes = hypothesis from a test of 20 tasks.

  • Top tier (Opus 5.5, US$ 4/20) · tokens R$ 0.15 + review 1 min R$ 0.50 = R$ 0.65 · month ≈ R$ 774
  • Mid tier (Sonnet 5.5, US$ 2/10) · R$ 0.07 + review 1.5 min R$ 0.75 = R$ 0.82 · month ≈ R$ 987
  • Mid tier (Grok 4.7, US$ 2/6) · R$ 0.06 + review 1.5 min R$ 0.75 = R$ 0.81 · month ≈ R$ 971
  • Open local (Qwen3.8-27B) · tokens R$ 0 + hypothetical fixed R$ 600/month (R$ 0.50 per task) + review 2 min R$ 1.00 = R$ 1.50 · month ≈ R$ 1,800

Takeaway: in this example, the most expensive token gives the cheapest task, because review weighs more than the token. With different review minutes, the order changes: that is why you measure.

  • Comparing only the token price and forgetting human review.
  • Using prices from memory: prices drop with each generation; always add the date and link.
  • Thinking local is free: it takes a machine, power, and someone to maintain it.
  • Choosing without the risk questions: the cheapest one may send customer conversations abroad without a contract.
