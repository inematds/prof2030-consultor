Lesson 3 · 18 min

Value × feasibility (and when NOT to use AI)

Discovery always brings more ideas than the company can take on. If you don't choose, the owner picks the flashiest one. The value and feasibility matrix puts the opportunities side by side, and the "when not to use AI" test takes off the list whatever a simple rule solves better.

Start the lesson

In this lesson you will

  1. 1Calculate the value of an opportunity in reais per year
  2. 2Measure feasibility: data, integration, error tolerance, and owner
  3. 3The four quadrants and what to do in each one
  4. 4The three signs that AI is not the answer

Goal: prioritize opportunities in a value × feasibility matrix and discard the ones that don't need AI, with the reason written down.

01 · The simplest-solution ladder

Before the matrix, every opportunity goes through this ladder. Tap each step.

Test question for moving up a step: "what happens when it gets it wrong, and who notices?"

Rule: use the lowest step that solves it. Move up only with the reason written down.

02 · From catalog to decision

Four steps. The filled-in matrix is not the deliverable: the decision is.

1. Value in reais

Annual value ≈ occurrences per day × cost of each occurrence × working days. Cost includes people's time (minutes × hourly cost), rework, and lost sales.

Value that doesn't turn into a number (reputation, risk) goes in as high, medium, or low, but it doesn't replace the math.

Horizonte, simulation60 quotes per day × 12 min of salesperson time at R$ 40/h (R$ 8) × 250 days ≈ R$ 120,000 per year in time alone.

2. Feasibility

Does the data exist, and can you get to it? Is the integration simple, or does it need a legacy system with no API? Is an error tolerable, or does it cause financial or legal damage? Is there an internal owner who will use it and look after it?

Each "no" lowers feasibility. Integration with a legacy system and changing the team's habits are the costs that hide the most.

Be wary when you hear"The data is already ready" and "the integration takes a week."

3. The four quadrants

Do now (high value, feasible): 30-day pilot. Plan (high value, hard): prepare data or process first. If time allows (low value, easy). Don't do (low value, hard), with the reason written down.

Pick one, two at most, for the pilot.

A good first projectMeasurable in 30 days, visible to whoever approves it, with accessible data and little change to routine.

4. When NOT to use AI

Low volume (a few cases a month don't pay for the build). Fixed rule (it fits in an "if X, then Y"). Costly error with no human review (money, contract, health): there AI only helps, never decides.

One sign is enough to go down the ladder. Write down the reason: it is what protects the client from the next fad.

Quick test"If this gets it wrong 1 time in 20, is the damage tolerable?" If not, AI only with a person approving.

03 · Template: value × feasibility matrix

Paste it into a spreadsheet. Scores from 1 to 5; the reason is always written down.

Catalog + matrix (spreadsheet)
| # | Opportunity | Process step | Step (don't do/rule/AI in one step/agent) | Value R$/year (calculation) | Value 1-5 | Data 1-5 | Integration 1-5 | Error tolerance 1-5 | Internal owner 1-5 | Feasibility (average) | Quadrant | Reason |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 1 | <e.g.: quote draft> | <sales> | <AI in one step> | <60/day × R$ 8 × 250> | <4> | <3> | <3> | <4> | <5> | <3.75> | <Do now> | <data in the price spreadsheet> |

Quadrant: Value >= 3 and Feasibility >= 3 -> Do now | Value >= 3 and Feas < 3 -> Plan
           Value < 3 and Feasibility >= 3 -> If time allows | Value < 3 and Feas < 3 -> Don't do
Checklist: does it need AI?
[ ] Does the task involve language, images, or documents with no fixed format?
[ ] Does the volume pay for the build within 12 months?
[ ] Is there quality data for the model to use?
[ ] Is an error tolerable OR does a person review it before it takes effect?
[ ] Is there no ready-made tool that already solves it?
[ ] Will someone at the company keep this running?
Mostly "no" -> stay on the lower step (fixed rule or don't do).
Decision record (one line per opportunity)
<opportunity> | step chosen: <...> | why not the one below: <...> | why not the one above: <...> | review if: <e.g.: error above 10% or cost above R$ X/month>
Simulation: illustrative example
  1. Quote draft from WhatsApp · AI in one step · value 4, feas. 3.8 → Do now.
  2. Overdue invoice reminder · fixed rule · value 3, feas. 5 → Do now, no AI.
  3. Customer service summary · AI in one step · value 3, feas. 2 (data leaving the company without a contract) → Plan.
  4. Agent that sells on its own · agent · value 4, feas. 1.5 → Plan (after pilot 1).
  5. Weekly visit report · nobody reads it → don't do.
  6. Demand forecast · value 2, feas. 2 (messy history) → Don't do now.
  • Value assuming 100% adoption on day one: cut the first-year gain.
  • Choosing by the "wow": the sales agent is exciting, but it depends on pricing, inventory, and rules that aren't organized yet.
  • Dropping an idea with no reason: three months from now the idea comes back and you don't remember why it was dropped.

04 · Practice: prioritize Horizonte

Use what you gathered in lesson 2.

E1 · Catalog of 6 opportunities

25 min

List 6 Horizonte opportunities, each tied to a process step. For each one, pick the step on the ladder and work out the value in reais per year (you can use simulated numbers, marked as simulation).

Done when: all 6 rows have a step, a ladder step, and a value calculation that someone else can redo.

E2 · Matrix and decision

25 min

Give the feasibility scores, place each opportunity in a quadrant, and write the decision record for the first two.

Done when: the matrix has all 6 opportunities, at least one marked "no AI" or "don't do," and the reason for each discard is written down.
